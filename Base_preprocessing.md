# Базовый препроцессинг (Base preprocessing)

*← Назад к [[README]]*

#препроцессинг #риск-менеджмент #биллинг

**Базовый препроцессинг** — это фаза, где исходный запрос на проведение конкретной финансовой операции (применение конкретного финансового инструмента) преобразуется в обогащенный, проверенный и готовый к маршрутизации внутренний объект. Именно здесь обеспечивается безопасность, соблюдение лимитов и закладывается основа для принятия решения о том, как именно будет выполнен трансфер.

Препроцессинг выполняется **Business Services Layer** перед передачей сформированных цепочек трансферов в **[[Transfer_Engine]]**.

## Основные этапы препроцессинга

### 1. Валидация параметров операции

**Цель:** Проверка соответствия параметров запроса условиям обслуживания участника.

**Проверяемые параметры:**
- **Лимиты участника:** Суточные, месячные, транзакционные ограничения
- **Разрешенные типы операций:** Соответствие запроса доступным для участника сервисам
- **Географические ограничения:** Допустимые страны/регионы для операций
- **Временные ограничения:** Рабочие часы, выходные дни, технические окна
- **Валидность реквизитов:** Корректность банковских счетов, криптоадресов, номеров карт

**Результат:** Подтверждение корректности запроса или отклонение с указанием причины.

### 2. Риск-скоринг

**Цель:** Оценка рискованности операции для принятия решения о дополнительных мерах безопасности.

**Факторы оценки:**
- **Поведенческий анализ:** Типичность операции для данного участника
- **Сумма и частота:** Соответствие историческим паттернам
- **Географические факторы:** Локация инициатора и получателя
- **Репутационные данные:** Участие контрагентов в подозрительных операциях
- **Соответствие нормативам:** AML/KYC требования

**Возможные результаты:**
- **Низкий риск:** Обычное прохождение
- **Средний риск:** Дополнительное логирование и мониторинг
- **Высокий риск:** Требование дополнительной аутентификации или блокировка

### 3. Взаимодействие с третьими сторонами

**Цель:** Определение необходимости дополнительных процедур аутентификации и авторизации при необходимости.

**Примеры взаимодействий:**
- **3D Secure (3DS):** Дополнительная аутентификация для карточных операций
- **Strong Customer Authentication (SCA):** Двухфакторная аутентификация по PSD2
- **SMS/Push уведомления:** Подтверждение операции участником
- **Биометрическая верификация:** Для операций повышенного риска
- **Внешние scoring системы:** Запрос оценки риска у специализированных сервисов

**Результат:** Получение параметров, для проведения дополнительного взаимодействия участника или внешней системы для продолжения операции.

### 4. Биллинг и тарификация

**Цель:** Определение стоимости операции и сторон, ответственных за оплату комиссии.

**Процесс тарификации:**
- **Анализ тарифного плана участника:** Определение применимых ставок
- **Расчет базовой комиссии:** На основе типа операции, суммы, направления
- **Применение скидок/надбавок:** Объемные скидки, премиальные тарифы
- **Определение плательщиков/получателей комиссии:** Инициатор, получатель или разделение комиссии
- **Валютное конвертирование:** Расчет комиссии в валюте операции

**Результат:** Структура комиссий, включаемая в цепочку трансферов.

### 5. Специфичные шаги для конкретных операций

**Цель:** Выполнение дополнительной бизнес-логики, специфичной для типа финансовой операции.

#### Примеры специфичного препроцессинга:

**Кредитные операции:**
- Проверка кредитоспособности заемщика
- Валидация залогового обеспечения
- Формирование графика платежей
- Создание эскроу-счетов для обеспечения

**Инвестиционные трансферы:**
- Проверка инвестиционного профиля клиента
- Валидация соответствия рискам портфеля
- Расчет налоговых обязательств
- Формирование отчетов для регуляторов

**Зарплатные проекты:**
- Проверка трудовых договоров и штатного расписания
- Валидация налоговых вычетов и удержаний
- Формирование справок о доходах
- Интеграция с HR-системами для актуализации данных

**Международные переводы:**
- Проверка валютного законодательства
- Валидация кодов назначения платежа
- Формирование документов валютного контроля
- Проверка санкционных списков

**Криптовалютные операции:**
- Анализ блокчейн-адресов на принадлежность к санкционным спискам
- Проверка источника происхождения криптоактивов
- Расчет налоговых обязательств по криптооперациям
- Соблюдение требований по декларированию

## Результат препроцессинга

После прохождения всех этапов препроцессинга формируется **обогащенная цепочка трансферов**, содержащая:

- **Валидированные параметры операции**
- **Результаты риск-скоринга и примененные меры безопасности**
- **Параметры взаимодействия с третьими сторонами** (при необходимости)
- **Детализированную структуру комиссий** и ответственных за их оплату
- **Специфичные параметры операции** для корректного выполнения
- **Метаданные для аудита** и соблюдения регуляторных требований

Часть данных препроцессинга предназначена для последующей обработки в бэкофисе, часть инкапсулируется в объект обобщенного трансфера для его последующей передачи в [[Transfer_Engine]], составления плана исполнения и фактического выполнения операции.

**Важно** В общем случае на этапе препроцессинга и до роутинга, а точнее фактического проведения трансфера через конкретного провайдера, невозможно делать предположения как о точной суммме комиссии провайдера, так и о сумме самого трансфера. Поэтому окончательная структура комиссий должна определяться после завершения трансфера.

## Связанные концепции

- **[[Transfer_Engine]]** — получает результаты препроцессинга
- **[[High_Level_Design]]** — где происходит препроцессинг в архитектуре
- **[[Participant]]** — для кого выполняется валидация условий обслуживания
- **[[Provider]]** — учитывается при расчете тарификации
- **[[Transaction_Lifecycle]]** — препроцессинг как первая фаза жизненного цикла
